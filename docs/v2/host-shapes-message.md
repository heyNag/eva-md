# The message that goes with the host shapes prompt

## (a) To the agent, when you attach the file to a new chat

> The attached file, host-shapes-prompt.md, holds a task for you. Read all of it. The part before the first line of tildes is notes for me; the part between the two lines of tildes is your instructions. Do exactly what that part says, as if I had pasted it here. Write the report where it says (eva-host-shapes.md, or eva-host-shapes-run2.md if that file is already there). Change nothing else on this machine. Run only the commands it names. If you think you need anything else, stop and tell me what and why. Do not ask me to approve it.

## (b) A note to yourself

1. This is a companion to the second report, not a part of it. Run it on the same Mac, from the same folder, after the second report or on another day, once eva-md has had at least a day of normal use since the upgrade. It saves the host sittings the facts it settles. Expect 30 to 60 minutes of the agent's work.
2. Open a new Codex chat in the desktop app, in the git repository you used for the second report, from your normal home, in Codex's default mode, not full access: its sandbox blocks the network and writes outside the chat's folder and temp. Attach the file with message (a), or paste the part between the tildes.
3. Approve only the commands in rule 1 of the file: two scripts of section 0, which run `xcode-select -p` and a git check with `ssh-keygen` only in a temporary folder, with made-up files and a throwaway key, signing without your SSH agent; `eva-md version`, `eva-md audit capture` and `eva-md status --updates`, which write nothing; the hosts', the apps' and the tools' versions (`--version`, `defaults read` of an app's `Info.plist`, `command -v`); `git -C <wiki> config --get remote.origin.url` inside a script that prints only `ssh`, `https` or `other`; `python3 -I` on scripts in the temporary folder; `mktemp -d` and `rm -r` of that folder; and `echo`, `if`, `case`, `for`, pipes, `wc -l` and `>` into that folder or the report between them. Refuse any other eva-md command (setup, init, install, uninstall, upgrade, update, commit, maintain, index, system, inbox, mcp, hook, doctor), any codex exec or claude -p, any web search or fetch, any network command (curl, ssh, git fetch, pull, push or ls-remote), and anything that writes outside the temporary folder and the report file in the chat's folder. Deny any request for access to a folder.
4. The chat is captured like any other, and may be summarized into the wiki and pushed by the daily job. Its scripts read eva-md's records and config file, the hosts' session files and Codex's config file; inside themselves they compare folder names with your `exclude` and test prompts only against fixed strings, and they print only counts, buckets, days, yes or no, and names and words from lists written in the file, never one they found. A chat you put off the record, or in an excluded folder, is left out.
5. Its last section asks you four things. One needs your wiki project's settings page in your browser, read only, answered yes, no or don't know; another needs System Settings, General, Device Management, answered yes or no.
6. Read the report once. Before you bring it back, look for any name, path, title, quote, model name or service name, and strike it. Answer its last section a line each in general terms (no names, no settings' names), and bring the file back.
