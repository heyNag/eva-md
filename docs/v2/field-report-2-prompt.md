## What eva-md is

Hooks in Codex and Claude Code record each chat into a local inbox, with secrets removed. At a chat's start eva-md adds a short brief, labelled eva.md and marked as reference data; a prompt that strongly matches a saved statement gets it added, and one that names a system gets a pointer to its page. After a chat, a background job runs the host's own model headless to organize it into a wiki of thread, rules, knowledge and system pages; a daily sweep picks up idle chats. The wiki is a separate git repository, committed and pushed once a day. Read tools: `eva-md search`, `eva-md show`, a recall skill, and, when its MCP server is connected, `eva_search`, `eva_show` and `eva_status`. This release adds counters and three content-free reports: new rows in `eva-md status`, `eva-md status --updates`, `eva-md audit capture` and `eva-md doctor --report`.

## Where things are

- The program: `~/.local/share/eva-md/bin/eva-md`, maybe on PATH as `eva-md`. Its modification time is the upgrade's time.
- Config: `~/.config/eva-md/config.toml`. It names the wiki folder.
- State, `~/.local/state/eva-md/`:
  - `inbox/<project>/<host>-<session>.jsonl`, one file per session; fields include `turn`, `role`, `kind`, `agent`, `text`, `cwd`, `red` (redactions).
  - `updates/<date>.jsonl`: the background job's run log, kept 14 days. New in this release: `trigger`, `rejection`, `model_reported` and the outcome `busy`. Never print `session`, `project`, `thread`, `session_hashes`, `model`, `model_reported`, `model_note` or `degraded`; compare them in a script only.
  - `heartbeats/<host>/<event>.json`: per hook event, the last 20 runs, and since this release `week`: counts per UTC date, at most the last 7.
  - `catchup/`: a record per session of transcript recovery: `missing`, `blocked`, `elsewhere`, `reason`, and `headless` (a program's chat). It also holds paths, folders and a copy of the last entry: never print them.
  - `commits/<YYYY-MM>.jsonl`: each daily commit and push, with `outcome`, `reason`, `pages`, `push`, and `unstaged`, which holds page paths: count it, never print it. Also `commit/`, `logs/`, `cache/`, maybe `code-status.json` (it holds repository paths: count only) and `needs-trust.json`.
- Not faults by being there: `commit/push-retry` is a timer; every check sets its date, push due or not. `needs-trust.json` is written by install whenever the Codex plugin's files change, and only uninstall removes it; health treats the hooks as awaiting review only until a Codex chat-start hook has run after its date. A new date means the plugin changed, not that Codex asked for a review.
- Host session files: `~/.codex/sessions/`, `~/.claude/projects/`.
