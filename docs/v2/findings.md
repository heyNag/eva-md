### The product as a whole: goal, decisions, scope, roadmap, risks and known limitations

**Overall call.** Evolve, with three rebuilds. Keep capture, redaction, the inbox as source of truth, the deterministic brief, the validator's provenance rules and the test discipline: they are the proven or principled parts. Rebuild the promotion pipeline as staged, re-runnable consolidation; rebuild recall as one retrieval layer over all memory; rebuild storage without okf, and replace the branch-keyed thread model. Add an evaluation harness and a host-neutral core with adapters first, and rewrite the documents as per-component specs. Run the existing pipeline live before redesigning: no update, recall or daily commit has ever run on a real host, and that evidence is cheap.

### Capture path: the hook dispatcher, the inbox store, session markers and paths

**Overall call.** Rebuild the capture pipeline around a canonical event model; keep the primitives. Keep internal/paths, internal/freetext, the redaction pattern in inbox.append, session.Lock, the detached-spawn recipe, the guard list, Run's fail-closed shell, the removal ordering and the test discipline. Rebuild the dispatcher's capture body (signal, ingest and context-read as separate paths), the inbox schema and layout (event ids, turn structure, session-keyed storage, a project registry), the trigger code into a scheduler, and host parsing behind adapters. Add a provenance field, an ingest API and a capture audit. Six findings share one root: the stored unit is one line per hook event, in arrival order, under a mutable key, and each later need was bolted on around it.

### Redaction: the current rules, the frozen baseline and the union

**Overall call.** Rebuild the engine; keep the invariants and the test cases. The work is careful, but its contract (strings in, strings out, an imprecise frozen floor unioned at run time) fixes its two worst properties in place: it destroys ordinary facts about authentication for good, and it doubles cost on the hook's hot path. One owner decision must come first: whether the frozen-baseline rule protects true secrets or every removal the baseline ever made.

### Evaluation and testing: the accuracy suite, the live accuracy run, the latency benchmark, CI and the test strategy

**Overall call.** Keep the frame, rebuild the instrument, add the missing layers. Keep the script-first fact model, the 12 failure modes, the shared offline and live loop, the quota guards, test isolation and the benchmark's scenarios. Rebuild the scorer (fact-level, value-aware, with a precision side, black-box) and the scenario corpus. Evolve the live runner into a matrix runner with stored results, and the benchmark into a macOS gate. Add a continuation harness with baselines, a retrieval eval, a corpus audit, a cost ledger and a host canary. Reason: today's suite proves the code around the model and nothing measures the memory, so no redesign could be shown to be better.
