# LG-12: the redaction corpus, its rates, and the baseline as an oracle

**Plan:** section 6.1 (design 7), section 7 decisions 7 and 32, section 8 Stage 1 rows LG-12 and LG-26. **Design:** `docs/v2/working-papers/design/ledger.md` sections 10.3, 10.6 and 10.7 and its row LG-12 in section 20; `audit/redact.md` findings F2, F6 and redact-m2. **Size:** M. **Reviewers:** two (redaction). **Depends on:** LG-11, SEAM-0c (merged); decision 7, taken as recommended.

## Why

Nobody knows how many secrets v1 misses or how many facts it destroys. Every text is redacted twice, by the frozen baseline and the current rules: twice the cost in every hook, and facts such as `api_key_header: X-Internal-Api-Key` masked for good. This package measures the rules and makes the baseline a test, so a switch can let the current rules run alone. LG-26 changes rules under these figures.

## What to build

1. **A labelled corpus** in `internal/redact/testdata/corpus/`, with a README that states its format. Positives are credentials only (decision 32): each provider format the rules know, private key blocks, JWTs, URL passwords, Authorization values, a secret key's value in each shape (shell, YAML, JSON, TOML, URL query, connection string), command-line passwords, a password in prose, random tokens near a trigger word by character class and length, and the shapes the audit found kept (F2, redact-m2), recorded as misses, not fixed. Negatives: code, prose and docs, chat-like lines written by hand, SHAs, UUIDs, `op://` and `$VAR` references, and the facts of ledger.md 10.3's T3 row, labelled as facts. No file holds a whole secret: each is joined from parts at load, as the tests' `j(...)` does, or made by a seeded generator.
2. **Generators** from fixed seeds: provider formats, random tokens, and passwords in the line shapes of `TestNoSecretVersion1Removed`, each planted in a carrier text; 32-character hex keys after phrases such as "the staging token is".
3. **The current rules alone**, as production code in `internal/redact`: the driver's private-key step, then the current rules to their fixed point, with no call of the baseline. It returns a `Result` with no `FloorOnly` finding; a stopped scan keeps nothing.
4. **Rates.** A test computes, for v1's engine (`Redact` today) and for the current rules alone: recall for each positive class; the share of cases changed for each negative class; precision over all replaced spans; `fact_loss_rate`; `hex32_kept_rate` (at least 2,000 keys); `oracle_violations`. A secret is kept when the output holds any 6 consecutive characters of it. They live in `internal/redact/testdata/rates.txt`: a flag its header names rewrites it; otherwise the test fails on any difference, printing both tables. Under the race detector it may draw fewer samples and compare no figures.
5. **`TestOracle`**: for every labelled secret and at least 20,000 generated ones, if `baseline.Redact` does not keep it, the current rules alone must not keep it. If one is found, change no rule and do not loosen the measure: stop and report its class and case.
6. **The switch.** `internal/config/redaction.go` registers `RedactionCurrentRulesOnly = NewBoolSwitch("redaction_current_rules_only", false)`. `internal/redact` gets `SetBaselineAtRunTime(on bool)` and `BaselineAtRunTime() bool`, safe for concurrent use, on by default; `config.LoadContext` calls the setter with `!RedactionCurrentRulesOnly.On(c)` for every config it returns, `Default()` included (redact cannot import config: config imports identity, which imports redact). Off is v1, byte for byte. On, `Redact` and `Scan` run step 3 and never call the baseline. `RedactKnown` and `Identifier` do not change. The `redacted` hook is called only for texts redacted with the baseline, so LG-11's check against `redactV1` stays exact.
7. **`BenchmarkRedact`**: both engines on made-up Markdown replies with code that mentions tokens, at 2, 16 and 64 KiB, as sub-benchmarks that `-count` alternates.
8. **The rule in words.** `Redact`'s doc comment says that with the switch on (decision 7 of the plan) only the current rules run, and `TestOracle` holds them to the baseline. `AGENTS.md`'s bullet on `internal/redact/baseline` needs the same sentence: give its words in the report, and the lead writes it at the merge.

## Accepted when

- `scripts/linux-check.sh` passes, every existing test unchanged; `git diff --stat main -- internal/redact/baseline internal/redact/redact.go internal/redact/passwords.go` is empty.
- `rates.txt` is committed with both engines' figures and `oracle_violations 0` for the current rules alone; a test shows the rates test fails when one label changes.
- `TestOracle` passes, and a test shows it fails on an engine that keeps the value after `password=`.
- A test runs the current rules over the raw corpus files and finds no `Certain` finding.
- Switch on: idempotent, and `Apply(Scan(x)) == Redact(x)`, on 20,000 generated inputs; the baseline is called zero times while the whole corpus is redacted, counted by test; a text on which the engines differ is redacted each way according to a config file read by `config.Load`. Switch off: LG-11's tests, unchanged, hold the output.
- `go test -run '^$' -bench '^BenchmarkRedact$' -count 10 ./internal/redact` shows the current rules alone at most half of v1's median time at 16 KiB; report every size. If not, make step 3 cheaper without changing what it removes.
- `scripts/linux-gate.sh`, switch off, shows no gated figure worse than the gate's rule allows. Report the figures.
