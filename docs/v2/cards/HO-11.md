# HO-11: the install manifest

**Plan:** section 6.5 (design 3, and "Kept"), section 8 Stage 1 row HO-11. **Design:** `docs/v2/working-papers/design/hosts.md` sections 4.2, 4.5 and 15, and its row HO-11 in section 21; `audit/ops.md`, "miss-1" (OPS-07). **Size:** M. **Reviewers:** two (install may now remove files). **Depends on:** HO-10a and HO-10b merged (HO-10b rebuilds the same files); SEAM-0c and SEAM-0d, merged.

## Why

Install and uninstall refuse any file in eva-md's marketplace folders that the running binary does not render (`treeChanged` in `internal/install/install.go`). So a release that removes or renames a plugin file cannot install over the one before, and a rollback past a release that added one is refused. HO-20 must change the Codex plugin's files.

## What to build

1. **The switch.** `internal/install/manifest.go` (new) registers `ManifestSwitch = config.NewBoolSwitch("install_manifest", false)`. It decides only whether install starts a manifest where none exists. Off, with no manifest on disk, install, rollback and uninstall do exactly what v1 does. A manifest on disk is read and kept current whatever the switch says: no v1 release writes one, so a v1 machine sees no change, and a release can roll back over a later one's layout. `Preflight`, which loads no config, reads it as off.
2. **The file**, `<share>/install-manifest.json`: 0600, written with `paths.WriteFileAtomicAt` under the install lock, read with the no-follow `readAt` under a size limit. It holds `format` (1) and `units`, in `adapter.All()` order. A unit has `id` (`claude-code/plugin`; `codex/hooks`, generation 0 in hosts.md 4.3), `host` (the adapter's `ID`), `plugin` (`eva-md@eva-md`), `root` (`marketplace/<InstallName>`, under the share folder), `generation` (0, `codex/hooks` only) and `files`, sorted, each `{path, sha256, size}`: the path slash-separated under the root, the hash lower-case hex. A field this binary does not know, and a unit it does not render, are written back as they were; that unit's folder and registration are left alone (HO-20 decides). A format above 1, a path that is absolute, unclean or leaves its root, or a root outside `marketplace/` makes the manifest unreadable: install and uninstall refuse with one line naming the file, and change nothing.
3. **The rule.** In a unit's folder, a file is eva-md's when this binary renders it or the manifest lists it, and a folder when it holds such a file. One not rendered now goes with the folder swap; a listed file whose bytes differ from its hash is replaced, as v1 replaces its own. Anything else is foreign and stops install and uninstall with v1's message. With the switch on and no manifest, v1's closed list of rendered paths (the eight in each folder that 2026.11.5 to 2026.11.7 write, spelled out, not from `render`) is the manifest, so a v1 folder is adopted.
4. **Order.** Before its first change, install writes a manifest listing what is listed now and what it is about to render; once the hosts verify, it lists only what was rendered. A failed install's rollback puts the manifest's bytes back, or removes it if there was none. A run with nothing to change writes nothing. A dry run adds an action line for each file it would remove.
5. **Uninstall** makes the same check, removes the manifest with the plugin folders, and otherwise does what v1 does. The install record, `cli-paths.json` and their readers stay (HO-27's).
6. **The earlier layouts.** The three published releases, 2026.11.5, 2026.11.6 and 2026.11.7, render the same eight paths in each folder, so SEAM-0d's fixture of 2026.11.5 stands for all three: a test holds that the paths v1 renders equal that fixture's files. Layout changes are tested on made-up layouts, in the table of "Accepted when".

## Owns and may touch

`internal/install/manifest.go`, `manifest_test.go` and `manifest_upgrade_test.go` (new); in `internal/install/install.go` and `uninstall.go`, the ownership check, install's order and rollback, and uninstall's removal.

## Must not touch

`templates.go`, `templates/**` and every plugin byte; `record.go`, `host.go`, `mcp.go`; existing tests and testdata of `internal/install`; `internal/config/**`, `internal/update/**`, `internal/health/**`, `internal/host/**`, `cmd/eva-md/**`, `scripts/**`, the docs. The host literal count for `internal/install` stays 0.

## Accepted when

- `scripts/linux-check.sh` passes and no existing test has changed, SEAM-0d's included. Switch off with no manifest, no `install-manifest.json` is written, by test.
- A table of layout changes, each two "releases" given to install as two renders through an unexported parameter, not a package variable: a file removed; a file renamed; a folder removed; a file added, then a rollback to the release without it. Switch off, each is refused as in v1; on, each installs, the folders hold exactly what the second release renders, and the manifest's paths, hashes and sizes match the disk. It logs `layout changes that install cleanly: N of M` for both.
- With a manifest present, a foreign file and a foreign folder each stop install and uninstall, changing nothing.
- Over each `testdata/installed-*` fixture, switch on: install succeeds and the manifest lists what it rendered, a second run changes nothing, and uninstall removes the folders and the manifest. A test fails if v1's path list differs from any fixture's marketplace files.
- A later release's manifest, listing a file this build does not render, an unknown field and an unknown unit: install removes the file and keeps the field and the unit.
- An install failed after the swap leaves the manifest as it was, or absent; one whose rollback also fails (as in `TestIncompleteRollbackKeepsLoadableFiles`) leaves one listing every file in the folders, and the next install succeeds.
- Each unreadable form of item 2 stops install and uninstall, changing nothing.
- `go test ./internal/install -run TestManifest` runs the new tests. The new fixtures pass `TestFixture2026_11_5HoldsNoRealPath`'s check.
