# LG-10: the event model and the one reader

**Plan:** section 6.1 (designs 1 and 2), section 8 Stage 1 row LG-10, section 14.3. **Design:** `docs/v2/working-papers/design/ledger.md` sections 3 and 14, and its row LG-10 in section 20. **Size:** M. **Reviewers:** two (the record is privacy-bearing).

## Why

Five places in v1 decode the inbox, each a little differently, and none gives an event an identity or says whose words a text is. Every later package of the record, organizing and recall tracks builds on one reader. This package is that contract, and a first backend that reads v1's files as they are.

## What to build

A new package tree under `internal/ledger`. No v1 code changes and nothing calls the new package yet.

1. **The event model** (`internal/ledger/event`): types for an event, its id and reference forms, its kind, its author, its exposure marks, its marked cuts, and a session with its class. Follow ledger.md section 3 for fields and names, with these rulings from the plan, which win where they differ:
   - **Authors.** Typed by the user; pasted; chosen by the user from options the agent wrote; written by the agent; by a subagent; by the host; by a program; spoken by the user in a voice call; the front model's, for its request and its spoken lines; and unknown. An author is set only on positive evidence.
   - **Session classes.** A person's chat; a subagent's thread; a program's run; a thread that was opened and never run; the host's own housekeeping; unknown. A thread whose prompts arrive through a voice hand-over is a person's chat.
   - **The key that makes two events one** is separate from the id: the host's row id where there is one, otherwise the turn, the kind and the tool call's id or the line's position. Never text alone. The spec states it.
2. **A spec** of at most 24 KB beside the package (`internal/ledger/SPEC.md`): the model, the reference forms, the sameness key, what each author and class means and the evidence that sets it, and the invariants with the tests that hold them.
3. **The reader interface** (`ledger.Reader`), and **a read-only backend over v1's inbox files**. Reading a v1 inbox through it:
   - yields one event for each physical line, in order, with a sequence equal to the v1 line number, gap lines and repaired partial lines included, so every reference v1 wrote (`s:<sid8>#<line>`) resolves to the same text;
   - yields the same text as v1's own readers do for that line (use v1's reading code to check, do not copy its faults silently: where v1 skips or repairs a line, do the same and mark it);
   - **never yields the author "typed".** v1 has no evidence that a prompt was typed on Codex, and it files voice hand-overs and program prompts as the user's. An entry v1 stored as the user's prompt gets an author value of its own that means "filed by v1 as the user's prompt; not proven typed". An entry whose text begins with the voice hand-over wrapper (`<realtime_delegation>`) is marked as a wrapper and is not decoded here: decoding is LG-13's. Entries with an agent id are a subagent's. A prompt v1 stored as a host prompt event is a program's.
   - sets a session's class only from what v1's files show: a subagent's id, a program's start, an end event with no start and no turn, no turn at all; otherwise unknown;
   - marks a second copy of an event by the sameness key and counts copies for each session. It drops nothing.
   - honours v1's trust rules for inbox files and its off-the-record ranges exactly as v1's readers do: nothing off the record is ever returned. Reuse `internal/inbox`'s walker and trust check; do not write a second one.

## Owns and may touch

`internal/ledger/**` (new). Test fixtures under `internal/ledger/testdata/`, made up by hand or by a generator in the test.

## Must not touch

Every other path. In particular `internal/inbox`, `internal/hook`, `internal/catchup`, `internal/resume` and `internal/update` are read, not edited.

## Accepted when

- `scripts/linux-check.sh` passes.
- Golden files of the event codec round-trip.
- On a fixture v1 inbox (several sessions across two project folders; a gap line; a partial last line; an off-the-record range; a subagent's entries; a program's prompt; a voice hand-over wrapper; a duplicated entry; an entry over v1's text limit) the backend yields events whose sequence equals the line number and whose text equals what v1's reader returns for that line, by a test that calls both.
- A property test over generated v1 inboxes holds the same two things.
- No event from the v1 backend has the author "typed", by test. Nothing from an off-the-record range is returned, by test, under generated placements of the pause and resume events.
- A second copy is marked and counted and nothing is dropped, by test, with the cases: the same entry twice, two different replies in one turn (two events, no copy), the same command run twice in one turn (two events, no copy).
- The package imports no new module, and only eva's name appears in its text.
