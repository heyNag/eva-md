# ST-04: the migrator and the minimum reader version

**Plan:** section 6.2 designs 3, 6 and 7, section 10 items 3 and 4, decisions 2, 3 and 22, Stage 1 row ST-04 (shrunk). **Design:** `docs/v2/working-papers/design/store.md` section 9.1, its row ST-04 in section 17 and sections 4.3, 4.4 and 7.3. **Format:** `docs/spec/store-format.md` sections 5, 8 and 9. **Size:** M. **Reviewers:** two (it writes the store). **Depends on:** ST-01 (merged).

## Why

The cut-over (ST-07) turns a v1 wiki into a store in one step that must survive a crash; a binary that meets a store newer than it knows must stop, not misread it. This is that step's runner and the reader rule, proven on a made-up step. Nothing calls it yet; no v1 behaviour changes, so no switch.

## What to build

A new package, `internal/store/migrate`:

1. **The step**, the contract ST-07 builds step 1 to 2 against:
   ```go
   type Tree interface{ Paths() []string; Read(path string) ([]byte, error) }
   type Step struct{ From, To, MinReader int; Classes []string; Plan func(Tree) (Change, error) }
   type Change struct{ Write map[string][]byte; Remove []string; Counts Counts }
   type Counts struct{ Read, Written map[string]int; Removed, Unreadable, PeoplesSections, Protected, Unaccounted, HeldBack int }
   ```
   A step sees only the tree committed at HEAD: no clock, nothing of the machine. Count keys come only from `Classes`. A `Change` may not name `.gitattributes`, `.gitignore` or the two `.eva-md` files.
2. **`Run(ctx, root, step, Options) (Result, error)`**, with `Options{StateDir, LocksDir, StoreID, Writer, Label, Pass string}`.
   - The generation is `store.toml`'s `schema`, else v1's `schema_version` in `.eva-md/schema.toml`. At `To`: no commit. Not `From`: refused.
   - It takes `paths.TryLock(LocksDir, "store.lock")`, as ST-05 will, without waiting. Busy, or a dirty tree it did not leave: refused.
   - `Unaccounted` above 0, or a written line `wikigit.SecretLines` flags: no commit; `HeldBack` counts such files.
   - Else: a journal, `<StateDir>/migrate-journal.json` (pass, from, to, the commit before); the ref `refs/eva-md/before-schema-<To>` at the commit before, kept, outside what a push carries; the files, mode 0600; the four runner-owned files exactly as the spec's section 5 says (`store_id` kept, else `Options.StoreID`; `min_reader` the higher of the old and the step's; `epoch` kept, else 1); one commit on `main`.
   - The commit: by `eva.md on <Label> <<Writer>@machines.eva-md.invalid>` as author and committer, unsigned, subject `migrate: - (+<added> ~<changed> -<removed>)`, trailers `Eva-Pass`, `Eva-Kind: migrate`, `Eva-Writer`, `Eva-Ops`, `Eva-Schema: <To>`. Ids, counts and enums only.
   - A journal found at the start: go back to the commit before, or finish if HEAD is that pass's commit, and run again under the journal's pass.
   - `wikigit.Run` keeps the person's signing and sets no environment, so git runs here on `identity.GitEnviron` with `wikigit.Run`'s pins, `commit.gpgsign=false`, `core.symlinks=false` and the identity by environment, under `wikigit.GitTimeout`.
3. **`DryRun(ctx, root, step) (Counts, error)`**: the same plan; no lock, no write anywhere. `Counts.String()` is one line of numbers by class.
4. **The reader rule.** `const Known = 2`. `Check(root string, known int) (Access, error)` reads only `.eva-md/store.toml` (no symlink, 4 KiB at most) by hand, since toml stays in `internal/config`: `schema` and `min_reader` once each as integers, and `store_id`; other lines are ignored. `min_reader` above `known`: no read, no write, a `*TooOldError{StoreID, Schema, MinReader, Known}`, which is `ErrTooOld` by `errors.Is`. `schema` above `known`: read only. Missing or unreadable: neither, `ErrNoManifest`. `Notice(stateDir string, err error) (line string, say bool)` says it once per store id and `min_reader`, kept in `<stateDir>/reader-notice.json`; unrecorded, it says it again. The line: `eva.md: this memory needs a newer eva-md (schema <m>; this one reads <k>). Nothing was read or written. Run eva-md upgrade.`

## Owns and may touch

`internal/store/migrate/**` (new).

## Must not touch

Everything else; `internal/store/profile`, `internal/store/testdata`, `internal/wikigit`, `internal/identity` and `internal/paths` are only used. No command, status row or switch.

## Accepted when

- `scripts/linux-check.sh` passes; `TestMain` calls `testgitenv.Clear()` and `testlimits.Raise()`.
- A synthetic step 1 to 2, on a made-up v1-shaped wiki in a temporary git repository, carries each file but the four the runner owns to `legacy/v1/` and writes `index.md` and `README.md`. Its result passes `profile.Check` with no fault, and `config.LoadSchema` reads schema 2 with no instance, which v1's writers refuse. A second `Run` makes no commit.
- A child kills itself (SIGKILL) at each crash point a recording run lists: every file write, git call and journal write or removal. The rerun gives the clean run's tree id, one migrate commit over the commit before, a clean tree, no journal, and the first pass id once the journal was written.
- Two copies in two folders, with other writers, labels and passes but one store id, give one tree id.
- After `DryRun`, the store, its `.git` and the state folder hash as before, and its counts equal `Run`'s. A marker planted in paths and contents is in no count line and no commit message.
- `Unaccounted` 1, a flagged line, a busy lock or a dirty tree changes nothing, by test.
- With `GIT_AUTHOR_*` and `GIT_COMMITTER_*` set, and a global config that signs through a script that leaves a marker, the commit is eva.md's, unsigned, and no marker exists.
- A table test of `Check` covers each outcome, and `internal/store/testdata/fixture-store` with `known` 1 gives `ErrTooOld`. `Notice` says it once, again for a higher `min_reader`, and every time when its folder is read-only; the line holds no path and no library's name.
- Nothing but its own tests imports the package, and it imports no new module.

## As merged

Merged from `pkg/st-04-r1bb` on 2026-11-12, after two reviews, a fix round and a verification that accepted it, having killed the runner at points of its own choosing and read what the next run did. The lead's rulings, which the code holds:

- **The before ref is never moved.** `Run` refuses when `refs/eva-md/before-schema-<to>` already keeps a commit other than the one before the step, in one line that names the ref and says how to remove it, and it sets the ref with the old-value form of `update-ref`, so no other git can have moved it either.
- **A recovery puts back only what the cut run could have left** at a path: the bytes of the commit before, the bytes the step writes, or absence. A person's edit made since the crash stays, the run refuses as dirty, and the journal stays until the person undoes the edit.
- **A file v1's `.gitignore` hid is unaccounted for.** The store's `.gitignore` is `.tmp-*` alone, so a `.DS_Store`, a `*.jsonl`, an `/inbox/` or an `.eva-md/tmp/` in the work tree makes the runner refuse, unless the person's own exclude files hide it.

For ST-07, which this leaves open: most v1 wikis on a Mac hold a `.DS_Store`, so the runner would refuse them at the cut-over. ST-07's card settles it before it is built: either the format's `.gitignore` also hides the files the system writes, with the runner's owned files changed to match, or ST-07 removes or accounts for what v1 hid before it runs the step.

Owed, small: no test catches the dotted-key guard of the manifest's reader on its own, since both dotted rows of `TestCheck` come after a plain `min_reader` line and are refused as repeats. A row whose manifest holds only `min_reader.x = 1`, and one with the spaced form, close it.
