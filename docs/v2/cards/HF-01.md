# HF-01: the shapes of the hosts' records, as a read-only command (HF-00)

**Plan:** section 8, Stage 0, the HF-00 row as the lead's cut of 2026-11-11 left it (facts marked "by the field report"); section 13 for what the first report could not see. **Follows:** [CT-3](CT-3.md), [CT-3b](CT-3b.md) and [CT-4](CT-4.md), whose form it takes. **Size:** M. **Reviewers:** two (it opens the hosts' own records of a person's chats): the contract, and privacy; then a verifier. **Merges only after the owner has cut the counters release:** it changes what the binary builds, and it rides the release after that one.

## Why

The cut of the host sittings marked 51 facts as settled by a read-only look at the one real install: which row types the hosts write, which fields a row has, what order and gaps rows come in, how sessions are named. A file that had an agent write its own scripts for this was tried three times in a made-up home with markers planted in every value and key. Each trial found a new way for something of a person's to reach the report: a client's own name in a one-word field, a file's extension, a path in a traceback, a version's suffix, a key inside a content item, a chat counted as five because it had five copies, a word in another script that a filter of ASCII letters let through, a version written in full-width digits. Prose cannot hold that line. Code with fixed lists and tests can, as `eva-md audit capture` and `eva-md doctor --report` do.

## What to build

A read-only command, `eva-md audit shapes`, and a package `internal/ledger/shapes`.

1. **What it reads.** eva-md's inbox, through LG-10's reader, and its heartbeats and run records where a fact needs them; and the hosts' own session files, found by the listing the capture audit already makes, admitted by recovery's own path rules and opened by recovery's own opener. Nothing outside the hosts' folders of chats is listed or opened and no link is followed out of them. It opens no chat's working folder, runs no command, makes no network or model call, and writes nothing.
2. **What it prints.** One JSON document with a format number, eva-md's version and the day, as the doctor's report has. Every key and every string value in it is written in eva-md's own code. It gives counts, shares, sizes and gaps in time in fixed buckets, yes or no, and days. A count of 1 or 2 of anything is given as "under 3".
3. **Names come from fixed lists, and nothing discovered is printed.** A row's type, a field's name, an item's type or key, a payload's type, a one-word value: each is counted under its own name only when it is on the list for its level, below. Anything else is counted under `other`, with how many distinct other names there were and in how many chats, as numbers. The lists, which the builder checks against `internal/catchup/parser.go` and `internal/ledger/audit/host.go` and may shorten but not lengthen without saying where a name comes from:
   - Claude Code row types: user, assistant, system, summary, progress, attachment, file-history-snapshot, queue-operation. System subtype: compact_boundary.
   - Claude Code row fields: type, uuid, parentUuid, sessionId, promptId, prompt_id, timestamp, cwd, gitBranch, version, userType, entrypoint, isMeta, isSidechain, isCompactSummary, repeatsCompactSummary, isApiErrorMessage, isVisibleInTranscriptOnly, agentId, agent_id, turnOrigin, origin, subtype, level, message, toolUseResult, requestId, content, summary, leafUuid. Message fields: role, model, content, stop_reason, stop_sequence, id, type, usage. Content item types: text, tool_use, tool_result, image, document, thinking, redacted_thinking. Content item fields: type, text, id, name, input, tool_use_id, is_error, content, thinking, signature.
   - Codex row types: session_meta, turn_context, event_msg, response_item, compacted. Row fields: timestamp, type, payload, ordinal. Payload types: task_started, turn_started, user_message, agent_message, task_complete, turn_aborted, context_compacted, message, function_call, function_call_output, custom_tool_call, custom_tool_call_output, local_shell_call, reasoning, token_count, exec_command_end. Payload fields: type, id, cwd, source, originator, cli_version, forked_from_id, turn_id, turn_attribution, message, phase, last_agent_message, role, content, name, call_id, arguments, output, status, exit_code, outcome.
   - Values, counted by name only from these lists: Claude Code's entrypoint (cli, sdk-cli, sdk-ts, sdk-py, claude-desktop, claude-vscode); Codex's source (cli, vscode, exec, mcp, unknown, atlas, chatgpt) and originator (codex_cli_rs, codex_vscode, codex_exec, codex_sdk_ts, and the desktop app's); turnOrigin (human). A version is counted as its ASCII digits and dots, three numbers, and anything else as other.
   A field's VALUE is never printed or kept, in whole, in part or hashed, beyond the lists above. A field that holds free data (content, text, input, arguments, output, result, a tool's metadata, an environment) is never descended into for names.
4. **A chat is counted once.** Copies, resumes, forks and a subagent's files that carry another chat's id count with that chat, wherever a figure is "in how many chats".
5. **What is left out.** A session that was off the record at any time, by either side's record, and a session in a folder the hook leaves out, are not read for shapes: they are counted, and nothing else.
6. **The facts.** The report gives, for each fact of [host-facts.md](../host-facts.md) marked "by the field report" that shapes can settle, the figures that settle it under a key named for the fact's number (`F-001` and so on). The builder lists in its report which facts are settled in full, which in part (F-084 and F-085 lose the names that are not listed), and which cannot be settled by shapes and stay with the sittings (F-025, F-127 at least), each with why.
7. **Bounded.** Each file is read once, within the audit's limit on a row. The command has a time limit as the doctor's report has, and a part cut short says so.

## Accepted when

- `scripts/linux-check.sh` passes.
- The planted-marker test builds a made-up home for both hosts with a different marker in every place a value can sit and in every place a key can sit, and finds none in the output. It plants at least what the three trials found: a one-word value in originator, entrypoint and source; an object as source, with marker keys; a session file with another extension, with none, and one that cannot be opened; a version with a suffix, and one in full-width digits; a key inside a content item, inside a tool's input and output, and at a row's top level in six chats; a row type, payload type and subtype in six chats; a key of 41 characters; words in non-Latin scripts as a key, a row type and a value; one chat with five copies, five forks and six subagent files.
- A test asserts that every byte of the output is printable ASCII or a line end, and that every string in it is one the package's own lists hold.
- A count of 1 or 2 prints as "under 3": a test.
- A session off the record once, on either side, and one in an excluded folder, add to no figure but their own count: a test for each, with two homes that differ only inside such a session giving the same output.
- A file with the right name outside the hosts' folders, and one reached through a link out of them, are never opened: a test that fails if either is.
- The report's tests name a root through a link wherever a rule depends on a path, as macOS reaches its temporary folders and may reach a home.
- A reviewer's own mutations (a list widened to print what it found, a value printed, a free-data field descended into, the off-the-record rule dropped, the ASCII check dropped) are each noticed by a test.

## As merged

Merged from `pkg/hf-01-r11` on 2026-11-12, after two reviews, three fix rounds and four verifications, the last of them three closing verifiers at once (what counts as one chat, what the command can print, the package as a whole) and one more after the fix they asked for. The lead's rulings on the way, which the code and `docs/design.md` now hold:

- **A name on a list says where it comes from.** A name stays on a list when its entry names its source, in this repository or in a host's published source or documents, and a test fails on an entry with none. A fixed name that no row holds counts zero and can leak nothing.
- **Item 4, forks and threads on Codex.** A fork is joined to its chat by `forked_from_id`, a subagent's thread by `parent_thread_id`, by its source's `thread_spawn` and by `session_id`, which is the root thread's for every thread under it; each id is kept only as a hash. The join on `session_id` was checked against Codex's published source: two chats that are not one agent tree never share one.
- **What today's Codex leaves uncounted.** Codex's hooks give a subagent's thread the root's session id, so the inbox holds no session under the thread's own id, and the thread's file is counted by name under F-024 and never opened. The join reaches only threads whose hooks gave their own id. `docs/known-limitations.md` says what that does to F-024's figures.
- **Off the record, per session.** A fork or thread put out on its own, by its own rows or by eva-md's records, is left out alone and the chat it came from stays in; a thread or fork of it goes out with it. On Claude Code a subagent's file is part of its session and puts it out.
- **Three limits**, said in `docs/design.md` and `docs/known-limitations.md`: a folder no identity-cache entry holds is judged by its path alone; a Codex first record over 64 KiB is counted only as not identified; a session put out as not read whole is read no further.

Built since, on 2026-11-12, and verified, as test files only: two more cases for `TestACodexForkOrThreadPutOutAloneLeavesItsChatIn`, a chain of three threads under a thread put out, and a file still in that names two chats, one out from the start and one that goes out only through another file. Each runs in the orders of the ids that list the chat's own file first or last, 48 of 120 and 240 of 720; the verifier ran every order once by hand and all passed.
