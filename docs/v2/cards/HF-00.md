# HF-00: the recorder for the host sittings, and fixtures with every value made up

**Plan:** section 8 Stage 0 row HF-00 (its second half: real payloads and transcripts from scripted sessions, regenerated with made-up values "so nothing of an account or a machine reaches a public repository"), "What the host sitting must settle", section 15.3 step 4. **Fact sheet:** [docs/v2/host-facts.md](../host-facts.md), the first half. **Run-book:** [docs/v2/host-sitting-runbook.md](../host-sitting-runbook.md), which names every `hostrec` command this card builds. **Design:** the recorders merged into HF-00, in `docs/v2/working-papers/design/`: ledger section 13 (LG-03), hosts section 14 (HO-01), store section 16 (ST-00) and deliver section 12 (DL-01). **Size:** L. **Reviewers:** two: a recording made on a real account passes through this code, whose job is that nothing of it reaches the repository. **Depends on:** nothing. Nothing in eva-md changes, so there is no switch. **Parts:** the card is accepted on Part 1, for the run-book's core; Part 2 (item 8) may come later.

## Why

The run-book's Part 1 settles the sheet's seven core facts in three short sittings at a Mac, in an evaluation home; its Part 2 waits for the packages that need the rest. That needs a small recorder whose hooks keep what each host sends, and fixtures made from the recording for LG-13, LG-21, HO-20, EV-14 and DV-03. Everything typed and spoken in the recording is made up, but its paths, ids, times, the computer's name and the account's traces are real. So the fixtures keep every field name and shape and replace every value, and a check fails when a recorded value survives.

## What to build

A developer's command, `cmd/hostrec`, that no release or install builds, as `cmd/live-accuracy` is one; and a package, `internal/hostfacts`, that holds the recording's format, the value generator, the vocabulary and the checks, imported by `cmd/hostrec` and by tests only. Standard library only. All of it is Part 1 but item 8.

1. **Scratch plugins and folders, written by `hostrec setup --rec <dir>`.** The plugins go into `~/hf/marketplace/claude-code` and `~/hf/marketplace/codex`, both marketplaces named `hf-scratch`, with every hook's command an absolute path to `~/hf-tools/hostrec hook --host <h> --event <E>`, outside every plugin root.
   - **Claude Code, one plugin `hf-recorder`:** a hook with no matcher for each event of F-075; one exec-form hook naming `${CLAUDE_PLUGIN_ROOT}/scripts/hf-exec-check`, a script that runs the recorder and is never renamed (F-104); one naming `~/hf-tools/hf-missing-check`, outside the root (F-050); one with a two-second limit for the timeout step (F-092); the command `hf-pause-check`, one skill, the agent `hf-gardener`; and the MCP server `hf-scratch` (`hostrec mcp`), whose `hf_lookup` is marked to load at start (F-093).
   - **Codex, three plugins**, each with its manifest in `.codex-plugin/plugin.json`: `hf-hooks`, a hook for each event of F-120 with no matcher, a shell matcher and an `Edit|Write` matcher on PreToolUse (F-123), two SessionStart handlers, one declaring a context limit of 3,000 and one declaring none (F-125), the missing-binary hook naming `~/hf-tools/hf-missing-check`, and one skill, `hf-inside-skill` (F-150); `hf-tools`, with no hooks, holding the skill `hf-pause-check` and the MCP entry (F-151); `hf-hooks-two`, with one hook (F-159).
   - **The scratch folders**, with exactly this made-up content, each repository with one first commit by `HF Scratch <scratch@example.invalid>`, set as `user.name` and `user.email` in that repository's own config:
     - `~/scratch/alpha-orchard`, a git repository: `CLAUDE.md` holding the line `Made-up project notes. The project word is WILLOW-CANDLE.` (F-091); `orchard/plums.txt` with the three lines `made-up plum list`, `count: 12`, `colour: purple`; `orchard/pears.txt` with the four lines `made-up pear list`, `count: 40`, `crate: wooden`, `note: none of this is real`.
     - `~/scratch/beta-lantern`, a git repository: `lantern/wicks.txt` with the three lines `made-up wick list`, `wick one: amber`, `wick two: grey`; `lantern/oil.txt` with the line `made-up oil: amber, thin`.
     - `~/scratch/outside`, an empty folder; `~/scratch/long-notes`, with an `AGENTS.md` of about 70 KB of made-up text (F-134); `~/hf-tools/hf-missing-check`, a copy of the recorder's hook; `~/hf-tools/hf-linked-name`, a link to `~/hf-tools/hostrec` (F-029).
   - `setup` also writes the setup marker of "Must not touch", and the private folder `~/hf-private`, outside the recording folder: a key made for this recording (for item 2's hashes), and the names item 2 replaces. `pack` never includes `~/hf-private`; `teardown` removes it.
   - **Arming never changes a plugin's bytes.** `hostrec arm <name>` and `disarm` write `<rec>/arm.json`, which the hook reads. No arm renames, writes or removes anything under a plugin root or in a host's cached copy of a plugin, on either host. The arms: `start`, `start-9900`, `start-10100`, `start-probe <characters> declared|plain`, `stop-child`, `pretool-word`, `pretool-slow`, `async-word`, `subagent-word`, `compact`, `timeout`, `missing` (renames `~/hf-tools/hf-missing-check` only), `rules` (writes a rules file in the account's Claude Code folder, which `disarm` removes), `end-slow`, `net-job`, `timed`. Each returns the planted word, text, `systemMessage`, sleep or background job the run-book's step expects, with the run-book's words. **Every arm except `disarm` and the start-text probes (`start-9900`, `start-10100`, `start-probe`) also answers SessionStart with source startup, resume or clear with the start word `MARIGOLD-TUESDAY`**. `start-probe` writes a made-up text of the given length, ending in a planted word, through the handler with the declared limit or the one without. The `timed` arm makes every second hook start also hash a made-up folder of 2 KB before it exits (F-173).
   - **Only `plugin-edit` changes plugin bytes**, and only as the run-book names: one byte of a skill in `hf-tools`, one of `hf-inside-skill`, one timeout in `hf-hooks`, a stray `.DS_Store` and a made-up symbolic link in Codex's cached copy, a timeout in `hf-recorder`.
2. **The hook, `hostrec hook`.** While a sitting is open (from `hostrec mark` to `hostrec close`), it reads the payload from stdin and appends one JSON line to `<rec>/events.jsonl`. While no sitting is open it writes nothing and exits 0 with `{}`. A line holds:
   - the step mark in force, the arrival time (wall clock and a monotonic reading), the host, the event, and **the payload whole**, with beside it the keyed hash (below) of each of the payload's string values, by field path;
   - the hook's start cost, from its parent shell process's creation (read from the process table) to the hook's exit; the parent's name and whether it is a login shell (F-162, F-173);
   - for the payload's working folder, whether git's HEAD is detached and the shape of its common git directory (F-127); the **names** of its environment variables, never a value, and whether the run-book's made-up marks are among them (F-023, F-028, F-029);
   - the count of files added under the host's folder since the step's mark, by name pattern only (F-024, F-125);
   - a **snapshot of the record file the payload names**: its size and modified time, and for each row added since the last snapshot of that file, its byte offset, its size, its row type, and its field paths with their JSON types. For each value in the row:
     - a boolean is kept;
     - a string at a field path on a closed **allowlist of enum fields** (`type`, `role`, `subtype`, `source`, `reason`, `entrypoint`, `isSidechain`, `isMeta` and the like, in `internal/hostfacts`) is kept when it is at most 32 characters of lowercase letters, digits, `_`, `-` and `.`;
     - a string of an **id shape** on a closed list (a UUID; `toolu_`, `call_`, `msg_` or `resp_` followed by letters and digits) is kept as it is, as the payloads already carry such ids whole;
     - every other string is kept as its length, its keyed hash, and, when it begins with a host wrapper's tag on the vocabulary, that tag's name. Never its text;
     - every other number is kept as its sign and its count of digits.

     The keyed hash is HMAC-SHA-256 under the key in `~/hf-private`, cut to 16 hex digits. Equal values in a payload and in a row have equal hashes, so the recording shows that a turn id, a tool-use id or an earlier session's id is on a row (F-001, F-002, F-033), that Stop's reply equals the record's reply row (F-004), and how many wrapper-shaped rows match no payload (F-147). Without the key, which never leaves the evaluation home, a hash says nothing of its value. The snapshot also says whether the turn's reply row, prompt row and turn-start row are present at that moment (F-019, F-122).

   **Before anything is written, by any `hostrec` command, to any file under `<rec>`**, these are replaced by fixed placeholders wherever they occur, matched without regard to letter case, with spaces and apostrophes normalised: the evaluation account's user name, full name and home path; the short name, full name and home path of every other account on the Mac, read once by `setup` from the system's user list and kept in `~/hf-private`; the Mac's ComputerName, LocalHostName, HostName and the output of `hostname`; and the scratch remote's host, port, namespace and path once `remote set` has stored it. Then the hook does what the arm asks. It fails closed: any error, a full disk included, ends with exit 0, `{}` on stdout and one line in `<rec>/errors.jsonl`. Its own work is bounded, so it stays far under the hosts' time limits.
3. **The MCP server, `hostrec mcp`**, over stdio: `hf_lookup`, whose answer ends with a made-up token `r:` and eight hex digits (F-036); `hf_big`, which returns a made-up result of the size asked for with a planted last word (F-039); one resource holding `MOSS-DIAL` (F-041); instructions longer than 4,096 characters with planted words at about 400, 3,900 and 5,000 characters (F-037). While a sitting is open it logs its process id and start, each request's field names and its environment's names (F-040), stamps a time every minute, starts one short child process (F-044), and stamps receipt and reply for each call (F-042). `hostrec lookup <term>` gives the same answer by command.
4. **The other commands the run-book names:**
   - `mark <step>` (opens the sitting if it is closed), `close`, `note`, `tail` (one line per event since the current mark: time, host, event; never a payload), `trust` (Codex's read-only `hooks/list`, as `internal/health` asks it);
   - `register [claude-code|codex] [<plugin>] [--config-dir <dir>|--codex-home <dir>]`, `register --check`, and `unregister [claude-code|codex|all] [<plugin>]`: the hosts' own commands to add or remove the scratch plugins (by default `hf-recorder`, `hf-hooks` and, with Part 2, `hf-tools`, of which `register` adds only those a host lacks; `hf-hooks-two` only when named), each with stdin closed and no terminal, recording its exit status and whether it asked anything; a command that fails is tried once more without `--json`, and the forms tried are printed for the owner to type the last by hand. `--check` lists the scratch plugins each host has;
   - `remote set` (reads the address saved to `/Users/Shared/hf-scratch-address.txt`, refuses any repository not named `hf-scratch-plum`, shows the name for the owner to confirm, stores the address in `~/hf-private` and deletes the file) and `remote read [--again]` (step S0-12's reads, after one interactive SSH connection to accept the server's host key);
   - `key` (makes `~/.ssh/hf_scratch_deploy`, an ed25519 key with no passphrase, in the evaluation account only, and writes its public half to `/Users/Shared/hf-scratch-deploy-key.pub`);
   - `machine` (the store's git checks of F-185 to F-188, F-195 to F-197, in a scratch folder);
   - `agent install|first-run|kick|times|remove`: the launchd user agent of steps S0-11 and S0-13; its tick, which appends a time to the recording, is the one writer that runs while no sitting is open;
   - `push` (step G-04, with the deploy key per call and no agent; on first contact it accepts the server's host key into its own known-hosts file in `~/hf-private`, never the account's, showing the fingerprint on screen only; it records the outcome by class), `deploy-key` (whether `gh` or `glab` has a write deploy-key command, signing in to nothing), `force-lease`, `keychain-names` (the service or label of login keychain items added or changed between `before` and `after`, never an account attribute), `swap-binary` (two builds that differ only in a version string), `plugin-edit`, `children`, `memory-index`, `cli-report` (waits for Enter while the owner switches the network off and on), `timing`, `voice-check`, `summary <sitting or group>`, `scan`, `scrub`, `pack` and `teardown`.

   Each does what its run-book step says, and prints counts, states and field names, never a row's text. `voice-check` also reports the field paths of any version or model field the voice wrapper or the session file's rows carry, the value of such a field only when it names the voice feature's version, and the byte count of the talk between hand-overs.
5. **Fixtures: `hostrec fixtures --rec <dir> --out internal/hostfacts/testdata/<host>/<version>/`.** It refuses a `--rec` path inside any git checkout. It keeps every field name that is on the vocabulary, the nesting, each JSON type and each array's length, and replaces every value with a made-up one of the same shape from a seeded generator: a string by one of the same length and the same character classes, with a path kept a path of the same depth, an id an id of the same form; a number by one of the same sign and magnitude. **A key is a value unless it is on the vocabulary**: an object key shaped like a path, an id, an email address, a host name or a version is replaced like any value. **Times:** the first recorded time maps to a made-up epoch, in a year before any recording and offset by a number of seconds that is not a whole number of minutes; every later time keeps its gap from the first; every time is written in UTC with `Z`, those in file names included. The same recorded value always maps to the same made-up value within a recording, and a snapshot's hash maps to the same made-up value as the payload value with the same hash, so ids still join events to rows in the fixtures. Values on a closed **vocabulary** are kept: event names, row types, source and reason values, tool names, field values such as `user` and `assistant`, booleans, exit codes under 256, and the tag names of host wrappers (the voice wrapper's among them), which are kept inside a string while the text between them is replaced. **Never on the vocabulary, and always replaced:** model names and aliases, effort levels, plan or tier names, host, app and operating system versions, and usage, cost or rate-limit figures, even when a host writes them on every row. The vocabulary is one committed file, `internal/hostfacts/vocabulary.json`, every entry of which the lead approves, as host words and not account words.
6. **The checks.**
   - `hostrec check --rec <dir> --fixtures <dir>` fails when a fixture holds, anywhere, in a key or a value, something from the recording that is not on the vocabulary: any string of four characters or more, or any number of four digits or more, compared whole and as a substring.
   - In the repository, a test rebuilds every committed fixture's values, keys included, from the generator's seed and each value's shape, and fails on any value the generator would not have made; for a time, it checks that the time is in UTC with `Z`, at or after the made-up epoch, and on the epoch's offset. The same test runs the email, home-path and token patterns of `scan` over every file in `testdata`.
   - `hostrec scan <dir>` asks once, never storing the answers, for the email address the owner signs in with, the owner's full name (required), the owner's own account's short name (with the user list's guess shown to confirm) and any other words. It searches every file of the recording for those, for the names of item 2, for every email address, and for anything shaped like a key or a token. It sorts hits by kind: values of a known host shape (UUIDs, `toolu_`-style ids, 40-hex hashes, `hf_lookup`'s `r:` tokens, the fingerprints and public halves of keys `hostrec` made) are reported as counts by kind, not as hits; only unexplained hits and hits on the words and names entered are shown, each with file and line. `scrub` replaces a hit everywhere with a made-up value of the same shape.
7. **The fact map.** `summary` reports, for each sitting fact with its mark, what the recording holds for it, and for each missing one the steps that settle it; Part 1's covers the core facts. For F-023 it also lists, by name pattern only, the session files under `~/hf-alt-claude` and `~/hf-alt-codex`. Its table lives in `internal/hostfacts` and a test holds it equal to the sitting facts and their marks in `docs/v2/host-facts.md`. `voice-check` compares the hand-overs' requests with the run-book's voice script, which `internal/hostfacts` holds as data, and a test holds that equal to the run-book's text.
8. **Part 2, which may be built later**, before the run-book's first Part 2 group: item 3 and `hf-recorder`'s entry for it; `hf-tools` and `hf-hooks-two`; `setup --more`, which adds them to a home Part 1 made, prints the hosts' update commands and rewrites no file Part 1 wrote; every arm but `start`; and `lookup`, `remote read`, `machine`, `agent`, `deploy-key`, `force-lease`, `keychain-names`, `swap-binary`, `plugin-edit`, `children`, `memory-index`, `cli-report` and `timing`.

## Owns and may touch

`cmd/hostrec/**` (new), `internal/hostfacts/**` (new), its `testdata/` included.

## Must not touch

Every other path. In particular eva-md's own plugins and their bytes (`internal/install`'s templates and everything SEAM-0d's hash test pins), `internal/hook`, `internal/health` (read, not edited), `AGENTS.md` and the cards' README. The recorder is never installed in a real home: `setup` refuses to run, and says why, when `HOME` holds an eva-md install record or config, or a `~/.claude` or `~/.codex` that already holds a session from before the evaluation account was made. On success it writes a setup marker in `HOME`. Every other `hostrec` command except `scan`, `scrub`, `fixtures` and `check` refuses to run unless that marker is present and the same eva-md and earlier-session check passes; the hook and the MCP server then exit 0 with `{}` and write nothing. No test runs a real host CLI, reaches the network, or reads or writes the real home; tests use fake `claude` and `codex` executables in a temporary folder.

## Accepted when

Part 1 on these for what it builds, Part 2 for what it adds.

- `scripts/linux-check.sh` passes, and `go list -deps ./cmd/eva-md | grep -c hostfacts` prints 0.
- `hostrec setup` in a temporary home writes the plugins and folders of item 1; a test holds that they declare every event F-075 and F-120 list, that every hook command is outside its plugin root, that every arm, run in turn, leaves the bytes of every scratch plugin unchanged (by hash), and that every arm but `disarm` and the start-text probes answers SessionStart startup with the start word. A test reads the run-book and holds that every scratch file it names exists as `setup` writes it, and that each line a step asks an agent to find or change is there when that step runs, whatever Part 2 groups ran before it (a `count:` line in `orchard/plums.txt`, `amber` in `lantern/wicks.txt`, the project word `WILLOW-CANDLE`, and the rest).
- Fed a made-up session (payloads on stdin, a transcript that grows between hooks, whose rows hold a planted sentence in every text field and the payload's ids), the hook writes one line per event with the snapshot of item 2; the planted sentence appears nowhere in the recording except inside a payload that carried it; the ids and the reply's hash join payload to rows; a made-up model id on every row appears nowhere outside the payloads; the evaluation account's names, another account's names, the computer's names and the scratch remote's host appear nowhere, in any file under `<rec>`. With no sitting open, the hook writes nothing. With the recording folder unwritable, with no setup marker, and with a malformed payload, the hook exits 0 and prints `{}`. By test.
- From a made-up recording, `fixtures` writes fixtures with the same field names, nesting, types and array lengths; ids still join across events and rows; a key shaped like a path is replaced; times are in UTC from the made-up epoch; `check` passes. A copy of one fixture with one recorded value put back, as a value or as a key, fails `check`, and fails the repository test without the recording. `fixtures` refuses a `--rec` inside a checkout. By test.
- `scan` finds a planted user name, full name, home path, computer name, email address and token-shaped string in a made-up recording, counts session ids and `r:` tokens by kind without showing them, and `scrub` removes each hit everywhere. By test.
- The fact map names every sitting fact of `docs/v2/host-facts.md`, with its mark, and no other, and `voice-check`'s script equals the run-book's. By test.
- Every `hostrec` command the run-book names exists (its Part 2's once Part 2 is built), by a test that reads the run-book.
- No new module; only eva's name in any output; nothing sleeps in a test to decide an outcome.
