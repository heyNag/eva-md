# HF-00: the recorder for the host sittings, and fixtures with every value made up

**Plan:** section 8 Stage 0 row HF-00 (its second half: "real hook payloads and transcripts from scripted sessions with made-up content, for both hosts, regenerated from the recordings' field names and shapes with made-up values so nothing of an account or a machine reaches a public repository"), "What the host sitting must settle", section 15.3 step 4. **Fact sheet:** [docs/v2/host-facts.md](../host-facts.md), the first half. **Run-book:** [docs/v2/host-sitting-runbook.md](../host-sitting-runbook.md), which names every `hostrec` command this card builds. **Design:** the recorders the plan merged into HF-00: `docs/v2/working-papers/design/ledger.md` section 13 and its row LG-03, `hosts.md` section 14 and its row HO-01, `store.md` section 16 and its row ST-00, `deliver.md` section 12 and its row DL-01. **Size:** L. **Reviewers:** two: a recording made on a real account passes through this code, and its whole job is that nothing of that account reaches the repository. **Depends on:** nothing. Nothing in eva-md changes, so there is no switch.

## Why

The plan's Stage 0 replaces inference about the hosts with measurement. 141 facts of the sheet are settled by the owner in three sittings at a Mac, in an evaluation home, following the run-book. That needs a small recorder whose hooks keep what each host sends, and a way to turn the recording into test fixtures that LG-13, LG-21, HO-20, EV-14 and DV-03 build on. The recording is made on the owner's subscription and machine. Everything typed and spoken in it is made up, but paths, ids, times, the computer's name and the account's traces are real. So the fixtures keep every field name and shape and replace every value, and a check fails when a value from the recording survives.

## What to build

A developer's command, `cmd/hostrec`, that no release or install builds, as `cmd/live-accuracy` is one; and a package, `internal/hostfacts`, that holds the recording's format, the value generator, the vocabulary and the checks, imported by `cmd/hostrec` and by tests only. Standard library only.

1. **Scratch plugins, written by `hostrec setup --rec <dir>`** into `~/hf/marketplace/claude-code` and `~/hf/marketplace/codex`, both marketplaces named `hf-scratch`, with every hook's command an absolute path to `~/hf-tools/hostrec hook --host <h> --event <E>`, outside every plugin root.
   - **Claude Code, one plugin `hf-recorder`:** a hook with no matcher for each event of F-075; one exec-form hook naming `${CLAUDE_PLUGIN_ROOT}/scripts/hf-exec-check` (F-104); one naming `~/hf-tools/hf-missing-check` (F-050); one with a two-second limit for the timeout step (F-092); the command `hf-pause-check`, one skill, the agent `hf-gardener`; and the MCP server `hf-scratch` (`hostrec mcp`), whose `hf_lookup` is marked to load at start (F-093).
   - **Codex, three plugins**, each with its manifest in `.codex-plugin/plugin.json`: `hf-hooks`, a hook for each event of F-120 with no matcher, a shell matcher and an `Edit|Write` matcher on PreToolUse (F-123), two SessionStart handlers, one declaring a context limit of 3,000 and one declaring none (F-125), the missing-binary hook, and one skill, `hf-inside-skill` (F-150); `hf-tools`, with no hooks, holding the skill `hf-pause-check` and the MCP entry (F-151); `hf-hooks-two`, with one hook (F-159).
   - `setup` also makes the scratch folders the run-book names, with made-up content only: `~/scratch/alpha-orchard` and `~/scratch/beta-lantern` as git repositories, `~/scratch/outside`, and `~/scratch/long-notes` with an `AGENTS.md` of about 70 KB of made-up text (F-134). It prints the registration commands of the run-book's step S0-06.
   - **Arming never changes a plugin's bytes.** `hostrec arm <name>` and `disarm` write `<rec>/arm.json`, which the hook reads. The arms are those the run-book names: `start`, `start-9900`, `start-10100`, `start-4900-declared`, `start-9000-declared`, `start-4900-plain`, `start-9000-plain`, `stop-child`, `pretool-word`, `pretool-slow`, `async-word`, `subagent-word`, `compact`, `timeout`, `missing`, `rules`, `end-slow`, `net-job`, `timed`. Each returns the planted word, text, `systemMessage`, sleep or background job the run-book's step expects, with the words the run-book prints (`MARIGOLD-TUESDAY` and the rest). Only `plugin-edit` changes plugin bytes, and only as the run-book's steps name: one byte of a skill in `hf-tools`, one of `hf-inside-skill`, one timeout in `hf-hooks`, a stray `.DS_Store` in Codex's cached copy, a timeout in `hf-recorder`.
2. **The hook, `hostrec hook`.** It reads the payload from stdin and appends one JSON line to `<rec>/events.jsonl`:
   - the step mark in force, the arrival time (wall clock and a monotonic reading), the host, the event, and **the payload whole**;
   - the hook's start cost, from the moment its parent shell process was created (read from the process table) to the hook's exit; the parent process's name and whether it is a login shell (F-162, F-173);
   - for the payload's working folder, whether git's HEAD there is detached, and the shape of its common git directory (F-127);
   - the **names** of its environment variables, never a value, and whether the run-book's made-up marks are among them (F-023, F-028, F-029);
   - a **snapshot of the record file the payload names**: its size and modified time, and for each row added since the last snapshot of that file, its byte offset, its size, its row type, its field paths with their JSON types, and only those values that are booleans, numbers, or strings of at most 32 characters made of lowercase letters, digits, `_`, `-` and `.`. Never any other text of a row. And whether the turn's reply row, prompt row and turn-start row are present at that moment (F-019, F-122).

   Before a line is written, the evaluation account's user name, its home path, the computer's name and the host name are replaced by fixed placeholders wherever they occur. Then the hook does what the arm asks. It fails closed: any error, a full disk included, ends with exit 0, `{}` on stdout and one line in `<rec>/errors.jsonl`. Its own work is bounded, so it stays far under the hosts' time limits.
3. **The MCP server, `hostrec mcp`**, over stdio: `hf_lookup`, whose answer ends with a made-up token `r:` and eight hex digits (F-036); `hf_big`, which returns a made-up result of the size asked for with a planted last word (F-039); one resource holding `MOSS-DIAL` (F-041); instructions longer than 4,096 characters with planted words at about 400, 3,900 and 5,000 characters (F-037). It logs its process id and start, each request's field names and its environment's names (F-040), stamps a time every minute, starts one short child process (F-044), and stamps receipt and reply for each call (F-042). `hostrec lookup <term>` gives the same answer by command.
4. **The other commands the run-book names:** `mark`, `note`, `tail`, `trust` (Codex's read-only `hooks/list`, as `internal/health` asks it), `remote set|read`, `machine` (the store's git checks of F-185 to F-188, F-195 to F-197, in a scratch folder), `agent install|first-run|times|remove` (the launchd user agent of step S0-11, with everything its first run does), `push`, `deploy-key`, `force-lease`, `keychain-names`, `swap-binary` (alternates `~/hf-tools/hostrec` between two builds that differ only in a version string), `plugin-edit`, `children`, `memory-index`, `cli-report`, `timing`, `voice-check`, `summary`, `scan`, `scrub` and `pack`. Each does what the run-book's step says it does, and prints counts, states and field names, never a row's text.
5. **Fixtures: `hostrec fixtures --rec <dir> --out internal/hostfacts/testdata/<host>/<version>/`.** It keeps every field name, the nesting, each JSON type and each array's length, and replaces every value with a made-up one of the same shape from a seeded generator: a string by one of the same length and the same character classes, with a path kept a path of the same depth, an id an id of the same form, a time a time at a fixed offset that keeps order and gaps; a number by one of the same sign and magnitude. The same recorded value always maps to the same made-up value within a recording, so ids still join events to rows. Values on a closed **vocabulary** are kept: event names, row types, source and reason values, tool names, field values such as `user` and `assistant`, booleans, exit codes under 256, and the tag names of host wrappers (the voice wrapper's among them), which are kept inside a string while the text between them is replaced. The vocabulary is one committed file, `internal/hostfacts/vocabulary.json`, every entry of which the lead approves, as host words and not account words.
6. **The checks.**
   - `hostrec check --rec <dir> --fixtures <dir>` fails when a fixture holds, anywhere, a value from the recording that is not on the vocabulary: any string of four characters or more, or any number of four digits or more, compared whole and as a substring.
   - In the repository, a test regenerates every committed fixture's values from the generator's seed and each value's shape, and fails on any value the generator would not have made. So a value that slipped through, or a fixture edited by hand, fails without the recording.
   - `hostrec scan <dir>` searches a recording for the names and paths of item 2, any email address, anything shaped like a key or a token, and words the owner types once at its prompt (never stored), and prints each hit with file and line. `scrub` replaces a hit everywhere with a made-up value of the same shape.
7. **The fact map.** `summary` reports, for each fact the sheet marks for a sitting, what the recording holds for it, by fact number. Its table lives in `internal/hostfacts` and a test holds it equal to the sitting facts of `docs/v2/host-facts.md`. `voice-check` compares the hand-overs' requests with the run-book's voice script, which `internal/hostfacts` holds as data, and a test holds that equal to the run-book's text.

## Owns and may touch

`cmd/hostrec/**` (new), `internal/hostfacts/**` (new), its `testdata/` included.

## Must not touch

Every other path. In particular eva-md's own plugins and their bytes (`internal/install`'s templates and everything SEAM-0d's hash test pins), `internal/hook`, `internal/health` (read, not edited), `AGENTS.md` and the cards' README. The recorder is never installed in a real home: `setup` refuses to run, and says why, when `HOME` holds an eva-md install record or config, or a `~/.claude` or `~/.codex` that already holds a session from before the evaluation account was made. No test runs a real host CLI, reaches the network, or reads or writes the real home; tests use fake `claude` and `codex` executables in a temporary folder.

## Accepted when

- `scripts/linux-check.sh` passes, and `go list -deps ./cmd/eva-md | grep -c hostfacts` prints 0.
- `hostrec setup` in a temporary home writes the plugins of item 1; a test holds that they declare every event F-075 and F-120 list, that every hook command is outside its plugin root, and that every arm, run in turn, leaves the bytes of all four plugins unchanged (by hash).
- Fed a made-up session (payloads on stdin, a transcript that grows between hooks, whose rows hold a planted sentence in every text field), the hook writes one line per event with the snapshot of item 2; the planted sentence appears nowhere in the recording except inside a payload that carried it; the evaluation account's user name and home path appear nowhere. With the recording folder unwritable, and with a malformed payload, the hook exits 0 and prints `{}`. By test.
- From a made-up recording, `fixtures` writes fixtures with the same field names, nesting, types and array lengths; ids still join across events and rows; `check` passes. A copy of one fixture with one recorded value put back fails `check`, and fails the repository test without the recording. By test.
- `scan` finds a planted user name, home path, email address and token-shaped string in a made-up recording, and `scrub` removes each everywhere. By test.
- The fact map names every sitting fact of `docs/v2/host-facts.md` and no other, and `voice-check`'s script equals the run-book's. By test.
- Every `hostrec` command the run-book names exists, by a test that reads the run-book.
- No new module; only eva's name in any output; nothing sleeps in a test to decide an outcome.

## Left for the lead

- The vocabulary's entries, approved one by one before the first fixture is committed.
- The first fixtures, made from the owner's recording after the sittings, and each fact's result in the sheet. The recording itself is never committed.
