# HO-14: fake hosts that fail the way real ones do

**Plan:** sections 4.2 and 6.5 (designs 2 and 6), section 8 Stage 1 row HO-14. **Design:** `docs/v2/working-papers/design/hosts.md` sections 3.2, 4.1, 4.4, 12 and 14, and its row HO-14; `research/codex-surface.md` sections 1.7, 2.3 and 2.4 and "Facts the notes lack" 1 and 2; `research/claude-surface.md` sections 1.1 and 2.4. **Size:** S. **Reviewers:** one. **Depends on:** nothing. It changes nothing v1 does, so there is no switch.

## Why

v1 fakes the hosts in five test files. None of these fakes knows that Codex binds hook approval to a hash of the plugin's files, that a host's version changes that rule, or that an administrator can turn hooks or plugins off. So no test can show the failures that HO-20, HO-12, HO-27 and HO-43 exist to handle.

## What to build

`internal/hostfake`: imported only by tests, standard library only.

1. **One fake for both CLIs, in two forms.** `hostfake.New(root string) *Fake` keeps all state under `root`. `(*Fake).Run(ctx, cli string, args ...string) ([]byte, error)` has the signature of install's `runner` (`internal/install/host.go:33`). `(*Fake).WriteCLIs(bin string) error` writes `claude` and `codex` executables that answer the same way. They re-run the test binary, so a package that uses them calls `hostfake.Main()` first in its `TestMain`. The fake answers every host command v1 runs, plus Codex's `--no-daemon app-server --stdio` with `hooks/list` in the shape `internal/health/hosts.go` reads. It keeps the quirks v1's fakes model today: the 0.166.0 wording for a missing folder, a refused second add, and Claude Code 2.1.316's scoped remove. A test can make a command fail before or after it takes effect, or stall until its context ends.
2. **Trust bound to a hash, for Codex.** `plugin add` copies the plugin to `<root>/codex/plugins/cache/<marketplace>/<plugin>/local/`, and Codex loads that copy. Each hook has a positional key and two stored hashes:
   - the declaration's: event, matcher, command, timeout, async, statusMessage, and a context limit that isn't the default;
   - the content's: each file's path, size and bytes, skipping `__pycache__`, `.venv`, `*.pyc` and `*.egg-info`. A symlink fails the hash.

   `hostfake.CodexContentHash(dir)` is exported, so HO-20 can check its own helper against it. `(*Fake).Approve(cli)` stands for the person's review. No command the fake answers grants trust, and `--dangerously-bypass-hook-trust` is refused and recorded. `hooks/list` says `trusted`, `managed`, `modified` or `untrusted`.

   `(*Fake).Fire(ctx, cli, event, payload)` runs the hook's declared command from the loaded copy, with the payload on stdin, but only if the hook would run. A hook that isn't trusted is skipped. If the copy's hash has changed, the hook fails with "plugin contents changed; hook approval required". The declared timeout is recorded, not enforced. Claude Code asks for no approval and reloads its plugin in place on each `Fire`.
3. **A version switch.** `(*Fake).SetVersion(cli, v)`, which `--version` prints. Before 0.164.0, Codex binds plugin hooks to the declaration only. The defaults are Codex 0.167.0 and Claude Code 2.1.321.
4. **Policy flags.** `(*Fake).SetPolicy(cli, hostfake.Policy{...})` has five flags: Codex hooks forced off, Codex plugins off, Codex managed hooks only, Claude Code managed hooks only, and a blocked marketplace. Each has one stated effect on the CLI's output and on `Fire`, and nothing the fake answers lifts it. Managed hooks a test declares run without review.
5. **Sources.** The package doc lists each behaviour and wording with its source (a research section, a hosts.md section 14 fact, or a v1 test). It marks each as the fake's own choice until HF-00 records the real one, which applies to:
   - `--version`'s wording;
   - the trust words besides `trusted` and `managed`;
   - how a policy block shows;
   - the cache folder's last segment;
   - fact 3 (installing the same bytes again restores trust).

## Owns and may touch

`internal/hostfake/**` (new), `internal/install/hostfake_test.go` (new).

## Must not touch

Every other path. The existing fakes and their tests stay as they are: `internal/install/install_test.go`, `upgrade_test.go`, `cmd/eva-md/**`, `internal/health/**`, `internal/update/**`. Moving them onto this fake is each file owner's job.

## Accepted when

- `scripts/linux-check.sh` passes.
- There is a self-test for each case below, and the report names a one-line change to the fake that fails it:
  - a stray `.DS_Store` in an approved copy gives `modified` and a failed `Fire`;
  - the same bytes added again give `trusted`;
  - a `__pycache__` file keeps trust;
  - a symlink stops every hook;
  - a changed timeout, or a group inserted above eva-md's, needs review;
  - a new binary behind an unchanged command keeps trust;
  - an edited folder that isn't added again still runs the old copy;
  - at 0.163.0 a content change keeps trust, and at 0.164.0 it doesn't;
  - each policy flag gives its stated output, and no hook fires under it;
  - Claude Code runs an edited hook without approval.
- `Run` and the written CLIs give the same bytes and exit codes for the same commands, `hooks/list` included. `install.Inspect` through the CLIs reports eva-md as installed and valid.
- `internal/install/hostfake_test.go` runs these v1 flows on the fake, with the fake's root outside the home:
  - a first install, with Codex `untrusted` until `Approve`;
  - a reinstall that changes only the binary: no registration call, `NeedsTrust` false, still `trusted`;
  - the upgrade over the 2026.11.5 fixture, which was approved first: `NeedsTrust` true, Codex `modified`, Claude Code unaffected;
  - uninstall;
  - hooks forced off, which gives `ErrHooksOff`.

  In each flow, `NeedsTrust` agrees with the fake.
- A test fails if a non-test file outside the package imports it, or if it imports anything outside the standard library, or any `net` package.
- Nothing sleeps.
