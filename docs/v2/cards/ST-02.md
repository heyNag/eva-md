# ST-02: the storage properties, as tests against a reference model

**Plan:** section 6.2 (designs 3 and 4, its bars), the Stage 1 row ST-02 (shrunk); rows ST-05, ST-08 and IF-01; decisions 2, 21 and 22. **Design:** `docs/v2/working-papers/design/store.md` sections 7.1 to 7.5, 9.3 and 10 and its row ST-02; `docs/spec/store-format.md` (the spec). **Size:** M. **Reviewers:** one. **Depends on:** ST-01 (merged); shares no file with ST-03 or ST-04.

## Why

The store core (ST-05) must be held to crash safety, exactly once, protection, restore and replay before it is written. A property that cannot fail proves nothing, so each must catch a broken model. One machine only (decision 21).

## What to build

Nothing calls it and nothing v1 does changes: no switch.

1. **The store's interface**, `internal/store/api.go`, package `store`, types only. `Txn` (`Pass`, `Kind`, `Actor`, `Session`, `Covers`, `Ops`); `Op` (`Type`, `ID`, `Base`, `Fields`, `Evidence`, `Authority` of `model` or `user`, `Requires`); `Outcome` (`Result` of `applied`, `noop` or `refused`, `Reason`, `ID`); `Range` with the spec's coverage fields; `Result` (`Outcomes`, `Commit`); and `Store`: `Apply(Txn) (Result, error)`, `Plan(Txn) ([]Outcome, error)`, `Coverage(session string) ([]Range, error)`, `Close() error`. As store.md 7.1, but kinds are the spec's section 8 list, `session.append` replaces `episode.append`, and refusal reasons are `locked`, `verified`, `unreadable`, `hand_edit`, `conflict`, `secret`, `invalid`, `unknown_id`, `requires`.
2. **Fault points**, same file: `Step` (`recover`, `plan`, `journal`, `write` once per file, `stage`, `commit`, `finish`) and `Fault func(Step, int) error`. An error stops `Apply` there, with no rollback or cleanup; `Close` then only releases the lock and open files, as a process's death would.
3. **Ids**, `internal/store/ids.go`: `NewID(letter byte, pass string, op int) (string, error)` by the spec's section 3, its time part the pass id's time, so a retried pass mints the same ids.
4. **The reference model**, `internal/store/conformance`, in non-test files, for IF-01's store fake. Only its durable part (files, journal, commits, hand-edit record, remote) survives `Close` and a reopen. It does `item.create`, `item.revise`, `item.state`, `session.append` and `doc.acknowledge`, and refuses any other type as `invalid`. Locked and unreadable files refuse every operation; a verified file and an unacknowledged hand edit refuse each one without the user's authority. Hand edits are adopted at open as kind `human`. Its bytes need not follow the spec: a property compares a subject only with itself.
5. **The harness.** `Subject`: `Open(clock, Fault)`; `Files()`, path to bytes; `History()`, each `Commit` with pass, kind, covers and counts; `Items()`, each with id, path, base, kind, state, title and statement; `HandEdit(path, Edit)`, where an `Edit` is a change, a lock written as `locked: true  # note`, a verify or a garble. `Restorable` adds `Push`, `Lose` (the store folder only) and `Restore`. A seed gives a schedule: passes from a fake derive that covers the next range of a made-up record and finds its targets by title through `Items()`; hand edits; acknowledgements; a crash at each step, then a retry; pushes; a lost folder. The clock moves only between passes.
6. **The properties**, each a `CheckX(subject, seed) error` naming the property, seed and step, with a `RunX(t, newSubject, n)`:
   - **CrashSafety:** after a crash at any step and a reopen, files and history equal those before the pass or after it ran uncrashed. A pass `Apply` returned is never lost.
   - **ExactlyOnce:** a pass id is in history at most once, and once if it applied or covered anything; a retry returns the first outcomes and ids and makes no commit; `Plan` returns `Apply`'s outcomes and writes nothing; one seed gives one tree.
   - **Protection:** an operation aimed at a protected file is refused with its reason, its bytes unchanged, and the pass goes on: each other operation gets the outcome it gets without that one, unless it requires it. A locked item is byte-identical after 1,000 passes aimed at it.
   - **Restore:** after `Lose` and `Restore` it opens with its store id, and files, history and coverage are those of the last push, or empty if none.
   - **Replay:** coverage never shrinks but by `Lose`. After a restore the queue, the record less `Coverage`, is exactly what the pushed head leaves uncovered; once it is replayed, coverage is at least what it was and the items match by kind, state, title and statement.
7. **Broken variants**, set from `_test.go` files by unexported fields of the model, at least one a property: files written before the journal; a committed pass not looked up; a lock read only in its bare form; a refusal that drops the pass; coverage kept outside the tree; a queue from the local job list.
8. **`internal/store/conformance/PROPERTIES.md`**, at most 12 KB: each property in plain words, its source, its check and the variants that kill it.

## Owns and may touch

`internal/store/api.go`, `internal/store/ids.go` and their tests (new); `internal/store/conformance/**` (new).

## Must not touch

Everything else. `internal/store/profile`, `internal/store/testdata` and `docs/spec/store-format.md` are read only; a gap in the spec goes into the report.

## Accepted when

- `scripts/linux-check.sh` passes.
- Each `RunX` passes 1,000 seeds on the model, fewer under the `race` build tag as `internal/redact/race_test.go` does. No test sleeps, reads the wall clock, runs git or writes to disk.
- For each variant a test shows its property failing on a fixed seed. A test fails if PROPERTIES.md's table has a property no variant kills.
- A test that follows the imports of the non-test files under `cmd/` fails if it reaches `internal/store/conformance`.
- `NewID` is the same for one pass and index, differs by index, matches the spec's grammar and sorts by the pass's time.
- Only eva's name appears in the new text.
