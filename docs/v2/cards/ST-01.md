# ST-01: the store's written format and its profile checker

**Plan:** section 6.2, section 6.3 (the rulings table and designs 3, 5 and 6), decisions 1, 2, 3, 22 and 33, and the Stage 1 row ST-01. **Design:** `docs/v2/working-papers/design/store.md` sections 3 to 7 and its row ST-01; `derive.md` section 5.5 for the tag table. **Size:** M. **Reviewers:** one.

## Why

The codec (ST-03), the migrator (ST-04), the storage properties (ST-02) and every package that reads or writes memory need one written format to build against. Nothing may be left to a builder's guess: a field with no stated rule is how two packages come to disagree.

## What to build

1. **The specification**, `docs/spec/store-format.md`, in at most 24 KB, with no line over 400 characters. It states: the layout of a store; the id grammar (14 characters, sortable by time, safe between machines); each file format (an item, a workstream, a session file, a project identity record, the coverage record); every field with its type, who may set it and how it merges; the path classes; protection (locked, verified, unreadable, and a file changed by anything but the engine); the commit trailer grammar; the schema version, the minimum reader version and the epoch. Where store.md and the plan differ, the plan wins, and the spec says which line of store.md it overrides. The rulings it must carry:
   - **Kinds:** `fact`, `decision`, `constraint`, `procedure`, `rule`. **States of a workstream:** `active`, `merged`, `archived`. Working items of a workstream are next steps and open questions, each a line with an id.
   - **Tags of an item** as in derive.md section 5.5 (`stated`, `accepted`, `observed`, `suggested`, `external`, `echo`), set by code from the author of the cited span. The author values include the two for a voice call (spoken by the user; the front model's). An item that is the agent's reading keeps a label of its own, which the migration of v1's observed pages needs.
   - **A disagreement is a stored record in v2.0.** Name its fields: the item it sits beside, the operation that was refused, the span it cited, the reason (a lock, a verified mark, an unacknowledged hand edit, the user's authority, another project's item), and the date.
   - **A hand edit carries no authority until it is acknowledged.** This overrides store.md, which gives a hand edit a person's authority.
   - **A rule or a constraint holds the user's own words** (redacted, at most 240 characters) beside the model's sentence, and they are committed with the item (decision 33).
   - **Nothing volatile is committed:** no timestamp restamped on save; indexes, maps and rendered views are local state (decision 22). Short excerpts beside other kinds of item are not committed in v2.0.
   - **Commits** are eva.md's, one for each pass, with trailers that name the pass, the session and the model. The spec covers both answers to decision 3 (signed with a key eva.md makes for the machine, or unsigned).
   - **A frozen system page** has a place in the store, read through the same codec; say where and with which fields kept as they are.
   - **The page format stays conformant with OKF v0.2**, pinned by the commit of that specification, and no file in a store names the library eva-md v1 was built on.
2. **A profile checker**, a small package `internal/store/profile` with no caller yet: given a folder, it says whether the folder is a store that follows the specification, with one message for each fault that names the file, the field and the rule. It reads; it never writes.
3. **A fixture store**, written by hand under `internal/store/testdata/fixture-store/`, with at least: two projects; one item of each kind; an item with a successor and its predecessor; a protected item in each form; a hand-changed file; a disagreement; a workstream in each state; a session file with its coverage; a frozen system page. All values made up.

## Owns and may touch

`docs/spec/store-format.md` (new), `internal/store/profile/**` (new), `internal/store/testdata/**` (new).

## Must not touch

Everything else. In particular nothing under `internal/okfadapter`, `internal/wikigit`, `internal/knowledgepage`, `internal/threadpage` or `internal/systempage` changes.

## Accepted when

- `scripts/linux-check.sh` passes.
- The fixture store passes the profile checker; for each rule the checker enforces, a test makes a copy of the fixture with that one rule broken and the checker names it.
- A table at the end of the specification lists every field and path class with its rule; a test reads that table and fails if the checker has no check for a row, or a check for something the table lacks.
- The specification is at most 24 KB and no line is over 400 characters, by test.
- The specification names its source for each rule (the plan's section, or store.md's section it follows or overrides), so a reviewer can check a rule against its source.
