## Command-line surface

| Command | What it does |
| --- | --- |
| `eva-md setup [--dir <folder>] [--remote <url>] [--git-host <url>] [--host claude\|codex\|all] [--no-push] [--yes]` | First-run setup in a terminal: checks this Mac, stopping with the fix at the first thing missing, then asks for the wiki folder and remote, unless `~/.config/eva-md/config.env` gives them, then init, install and the health check; `--git-host` names, by any web address on it, the host where it may create the repo, with gh or glab as the host is GitHub or GitLab |
| `eva-md init --remote <url> --dir <folder> [--no-push]` | Clone or adopt the empty wiki repo, scaffold it through okf, validate, make the first signed commit, push, and write the per-machine config |
| `eva-md validate [--dir <folder>]` | Run okf Validate on the wiki (the configured one by default) and print counts only. Exits 1 on errors, orphans, broken links, or actor and parent-index warnings |
| `eva-md install [--host claude\|codex\|all] [--dry-run]` | Place the binary, generate both marketplaces, install and verify through the host CLIs, roll back only this run's steps on failure; then link `~/.local/bin/eva-md` when that folder is on PATH, and add to the install record |
| `eva-md uninstall [--apply] [--all] [--yes]` | Preview by default. `--apply` removes plugins, marketplace entries, marketplace folders, the binary and the link, in that order, keeping the inbox, config and wiki; `--all` also removes the config and the local data after `delete` is typed on a terminal, `--yes` or not, or with `--yes` without one. Never the wiki |
| `eva-md upgrade [--check] [--force] [--version TAG]` | Install the latest release, or `--version`, when it is newer than this binary, by downloading and checking it and running its setup; `--check` only says whether one is newer, `--force` installs one that isn't (see "The install scripts and upgrade") |
| `eva-md doctor [--json] [--live]` | Health report: PASS, FAIL or UNKNOWN on each line, with a one-line fix (see "Health check"). It has two repairs: it writes the names and repos indexes again when either is missing or out of date, and builds the knowledge map, folder index, recall index and root index line again from the pages when any is. `--live` runs the exact headless update command for each installed host on a fixture |
| `eva-md doctor --report` | Read-only: how eva-md has behaved on this Mac, as JSON of counts, durations, dates, its version and fixed names (see "Field report"). Exits 0 with its report, even when cut short, and 2 on a usage error, as with `--json`, `--live` or on `status` |
| `eva-md status [--json] [--updates]` | Local health without querying the hosts, plus the wiki's contents (projects, threads and knowledge pages) and the update backlog. It never writes: a missing or stale names or repos index, or knowledge files out of date, are a FAIL. With `--updates`, what the background update did and cost over the run log's last 7 days, in counts and durations only (see "Health check") |
| `eva-md brief [--cwd DIR] [--as startup\|clear\|compact\|resume\|fork] [--session ID] [--host claude-code\|codex]` | Print exactly what a new chat would receive |
| `eva-md show <s:id#line \| page[#section]> [--last N] [--since YYYY-MM-DD]` | Resolve a source ref to inbox entries, or print a page or one section of it. A section is streamed with bounded memory and ends where `threadpage.Parse` ends it, so a heading in a fenced block ends nothing. `#Now` and other named sections stop reading at the section's end. `#Timeline` shows the newest 10 date groups, or those `--last N` (1 or more) or `--since` choose, and `#<YYYY-MM-DD>` that day's group; both read the page once and stop at about 16 KB with a count of the lines left. A section is found by its heading or its anchor, in any case. A whole page over 2 MiB is refused. A wiki page is cleaned as the brief cleans text, but a line keeps its identifiers when the daily commit's scan passes it and it cleans the same alone as within the whole page, so a value made suspect by the line before stays redacted; a line holding an escape sequence is shown as plain cleaning leaves it. After a system page or a section of it, a line on stderr for each repo and commit the page cites, saying how far its code moved since the page's as_of and where that was measured, or why it couldn't be, and one once its review day has come, measured within 3 s (see "Code a system page cites"), then one naming the system pages that link to it; stdout stays the page. A knowledge page (`knowledge/k<N>`, its `#Statement` and `#History`) and `knowledge/map` show as any page, with nothing on stderr |
| `eva-md search <terms...> [--all] [--days N] [--limit N] [--cwd DIR] [--pages \| --inbox]` | Find earlier chat text in the inbox and lines of the thread, system and knowledge pages (`--pages` or `--inbox` for one of them): this project and the general area, or every project with `--all`; the last 90 days unless `--days` says otherwise (0 for no limit), though system and knowledge pages are always searched; the 10 best hits, or up to 50 with `--limit`, each with a ref for `eva-md show`. Run by the agent, never by a hook |
| `eva-md update [--session host:id ... \| --pending] [--sweep] [--dry-run] [--foreground] [--trigger NAME]` | Run the background update for the sessions named (`--session` once or more), or for every session with a backlog, under one global lock and the daily cap. `--sweep`, alone or with `--session` but not with `--pending` or `--dry-run`, also takes the day's sweep, at most once a day: up to 5 sessions of the whole inbox idle an hour or more with a backlog, newest first (see "Triggers"); a person's chat start adds it to its catch-up. `--foreground` runs attached with progress on stderr, as a person's manual run; without it, the lines go to the day's log. `--dry-run` takes one session, prints the next pass's exact command, environment names, rules, input and schema, and makes no call. `--trigger` names what started the job, for the run log, as the hooks pass it (see "Triggers"); a name eva-md doesn't know is recorded as `other`, and without it a `--foreground` run is `manual` and any other names none. The triggers spawn it detached |
| `eva-md maintain [--push-only]` | The daily job the hooks spawn: the knowledge files built again when they are out of date, the day's commit and push, unless `commits = false`, then the lint, the code status of the system pages, the pruning of old attempt markers and of the transcript-recovery records not saved for 30 days or past a host's newest 2,048, then the search index step, under its own lock (a busy run exits 0); without a wiki, only the search index step and the pruning. `--push-only` only pushes, while the newest commit record's push is pending. At most one line a step (the knowledge step only when it rebuilt something, or found the wiki busy and left it for the next run, and the records' pruning only when it removed some); exits 1 when a step was refused or failed |
| `eva-md index [--rebuild] [--json]` | Bring the search index up to date with the inbox now, as the daily maintain does, or with `--rebuild` build it again from nothing (see "Search index"). Optional: search scans whatever the index lacks. Prints a line for each project folder it indexed, merged or built again and a total, counts only, or with `--json` the index's status. A catch-up already running prints `index: busy` and exits 0; a failure exits 1 |
| `eva-md commit [--push-only]` | The daily commit and push now, with maintain's guards, or with `--push-only` a push of earlier commits. Prints one line, such as `committed (3 pages, 1 left out), push ok`; exits 1 when the commit was refused or failed, or a push-only run that ran didn't end `ok` or `up_to_date`; a run that found another one running (`busy`) exits 0 |
| `eva-md system write <slug> [--replace]` | Read one system page from stdin and write it with the map (see "System page"). Prints `wrote systems/<slug>.md (<n> bytes); the map has <m> systems`, then a line for each repo and commit of the code the page cites, saying the clone its paths were checked in or why they weren't; or each problem it refused the page for, by line, never the text. Exits 0 on a write, 1 on a refusal and 2 on a usage error |
| `eva-md system status [<slug>...] [--json]` | Measure how far the code the system pages cite has moved, or that of the pages named, in local clones, and save it as the code status the prompt hook and the doctor read (see "Code a system page cites"). Prints a line for each repo and commit, most moved first, one for each page past its review day, then the counts; `--json` prints the status. Exits 0 whatever the code did, 1 when the wiki can't be read or the status can't be saved, 2 on a usage error |
| `eva-md inbox clear [--session ID ...] [--project KEY] [--before YYYY-MM-DD] [--apply]` | Remove captured sessions whole, chosen by session, project and last write, each given narrowing the rest; a preview without `--apply`. Removes each session file with its watermark and, unless the chat is off the record, its recovery record, and the projects' search index, recording each session in `inbox/.removed` for the lint just before its files go; never the wiki (see "Removal" under "The inbox"). Exits 0 when done or when nothing matches, 1 when busy, on a failure or for 8 characters two sessions share, and 2 on a usage error, such as a filter given an empty value |
| `eva-md audit capture [--session ID \| --last N]` | Read-only: score each chat the inbox holds against the host's own record of it, and print numbers only (see "Capture audit"). Exits 0 with its report, 1 when the inbox or the config can't be read, and 2 on a usage error |
| `eva-md audit shapes` | Read-only: print, as JSON, the shapes of the hosts' records of the chats the inbox holds, and of eva-md's records of them, in counts and fixed names only (see "Shapes audit"). Exits 0 with its report, also one cut short by its time limit, 1 when the inbox or the config can't be read or the report holds a string no list holds, and 2 on a usage error |
| `eva-md inbox list \| show <session>` | Planned: inspect the inbox |
| `eva-md migrate [--apply]` | Later: schema migration, previewed first (only once a breaking change exists) |
| `eva-md hook --host claude-code\|codex` | Hook entry point (internal) |
| `eva-md version` | The binary's version, then `schema_version 1`, the wiki schema it reads and writes. A release binary's version is its tag, such as `2026.11.3`, which the release workflow sets with `-ldflags '-X main.version=<tag>'`: the same day a source build of that commit prints (see "Making a release"). A source build's version is calendar based and set by no one: the UTC day of the commit the binary was built from, as year.month.day, then as build metadata that commit's UTC time as hours and minutes and its short hash, as in `2026.11.2+0915.9e4f609`, with `.dirty` for a build of a changed working tree. It is a valid semantic version; the time sorts two builds of one day, which compare equal under semantic versioning's rules, and the hash names each one. Go records the commit in every binary built from a git checkout, and in the pseudo-version of a module it fetched; a build with neither, such as a test binary, is `dev`. The same version is the author, `eva-md/<version>`, of the pages eva-md builds itself, and the MCP server's `serverInfo` version. |
| `eva-md mcp --host claude-code\|codex` | The read-only MCP server the plugins start once a chat (internal; see "MCP server") |

The built commands are setup, init, validate, install, uninstall, upgrade, doctor, status, brief, show, search, index, inbox, audit, update, commit, maintain, system, hook, mcp and version; run with no arguments, eva-md lists them. The planned `inbox list` and `inbox show` print inbox's usage and exit 2; any other command, the planned `migrate` included, prints "unknown command" and exits 2.

- **Public wording** (`cmd/eva-md`). README.md, AGENTS.md, docs/*.md and every Go file under `cmd` and `internal` but the test's own, comments and test fixtures included, say a self-hosted GitLab, GitHub, a GitHub Enterprise server or a managed machine, with no workplace wording in prose, fixtures or example folders; the ordinary verb is fine (`TestThePublicRepoUsesNeutralWording`).

<!-- v1 docs/verification.md 040 -->
- **Docs that match the CLI and the tests** (`cmd/eva-md`, `internal/redact`).
  The usage line lists exactly the commands of the command table in `cmd/eva-md/table.go`, byte for byte as before the table (`TestUsageLineIsUnchanged`, `TestTheCommandTableIsWellFormed`), and the planned commands print what they did: `inbox list` and `inbox show` inbox's usage, `migrate` "unknown
  command", each exiting 2 (`TestTheDesignNamesTheBuiltCommands`); README's Commands list and the table show the same commands, and the table every flag README shows, as `--sweep` for update (`TestTheDesignShowsEveryFlagTheReadmeShows`); every source file of `cmd/eva-md` is named by a command of the
  table or by its list of support files (`TestAgentsNamesEveryFileOfTheCLI`), each of these checks is shown to catch a gap (`TestTheDocumentChecksCatchAGap`), and a hook never walks the table (`TestTheHookSkipsTheTable`); AGENTS.md's rule on what not to run against the real machine names each command
  README shows with `--apply` as an item of its own, not inside another such as the uninstall script, with its run without `--apply` among the previews (`TestAgentsPreviewsWhatTakesApply`); this file's count of the redaction test's kept lines is the test's own (`TestVerificationCountsTheKeptLines`),
  and each bullet that names its packages cites only tests that exist in them (`TestVerificationBulletsNameTheirPackages`); design.md's examples of the `PASS` and `PWD` keys behave as it says, a key that always loses its value losing an ordinary and a quoted one, and a judged key keeping an ordinary one (`TestDesignsPassKeyExamples`).

<!-- v1 docs/verification.md 041 -->
- **Only eva's name** (`cmd/eva-md`, `internal/wikiinit`, `internal/okfadapter`, `internal/config`).
  `eva-md version` prints the binary's version and `schema_version 1` and nothing else (`TestVersion`); no committed file of a new wiki names okf, with the Mac's name fixed so it can't match by chance (`TestInitPushAndAdopt`); `Init` writes eva-md's own root index and log, so okf writes neither, and
  keeps a wiki's own (`TestInitOpen`); a save that fails on the file system says the step that failed in eva-md's words, never with okf's temporary file or lock file, and keeps its errno, for a folder it can't write (`TestSaveFailureNamesNoTemporaryFile`), a wiki root it can't write, where okf takes
  its lock (`TestSaveFailureNamesNoLockFile`), and for each step of okf's atomic write, the rename included, and of its lock, a lock file okf waited for in vain being a busy wiki lock (`TestOkfFailure`); and a schema with keys this eva-md doesn't read loads with those it does (`TestLoadSchemaIgnoresKeysItDoesNotRead`).
